# Synergy IME Guard v0.1.1

This maintenance release fixes a long-running reliability failure in the
macOS Synergy server guard.

## What changed

- Fixed leaked pipe file descriptors from repeated `ps` and input-source
  subprocesses. After a long remote session, the leak could prevent new process
  snapshots and make the guard miss later cursor transitions.
- Consolidated each role and language-sync decision into one process snapshot.
- Tightened process matching so commands that only mention a `synergy-core`
  path cannot be mistaken for a running Synergy core.
- Reduced pending-restore health checks from every 0.5 seconds to every 5
  seconds. Cursor transition handling is unchanged and remains low latency.
- Added explicit diagnostics for process-snapshot failures and skipped leave
  events. A failed snapshot now preserves pending restore state and schedules a
  reconciliation retry instead of being mistaken for a stopped server.
- Added regression tests for repeated subprocess execution, input-pipe cleanup,
  discovery failure reporting and retry, executable matching, and
  single-snapshot decisions.

## Tested scope

- Synergy 3.6.3
- macOS 26.5.1 and 26.5.2 on Apple Silicon
- Simplified Chinese Pinyin and ABC
- Active Mac server and passive Mac client
- Universal arm64 and x86_64 release build

Windows and Linux remote clients remain inside the architecture boundary but
have not been physically tested. Deskflow is not yet claimed as supported.

## Verification

Download the archive and its `.sha256` file, then run:

```bash
shasum -a 256 -c synergy-ime-guard-v0.1.1-macos-universal.tar.gz.sha256
```

The executable is ad-hoc signed and is not Apple-notarized.
